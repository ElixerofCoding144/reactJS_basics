# What is the difference between "start" : "parcel index.html" and "build" : "parcel build index.html" mentioned in the script section of package.json?

- "start" : "parcel index.html"
  - Purpose: Local application testing and development.
  - Server: Starts a local server (usually http://localhost:1234).
  - File Watching: Active. Watches files and automatically updates the browser.
  - Code Optimisation: Fast compiling, skipping heavy minification
  - Source Maps: Enabled by default for easy browser debugging.
- "build" : "parcel build index.html"
  - Purpose: Final production deployment.
  - Server: No server is started.
  - File Watching: Disabled. Runs exactly once and stops.
  - Code Optimisation: Aggressive minification, tree-shaking, and compression.
  - Source Maps: Typically disabled or separate to minimize asset size.

> Once the script is updated in package.json, we can use the following commands: `npm run start` and `npm run build`. Note: `npm run start` is same as `npm start`.

# `React.createElement()` — What Happens Behind the Scenes?

> `React.createElement()` does **not immediately create an HTML DOM element**.

React first creates a **React Element**, which is a **JavaScript object** describing what the UI should look like.

Conceptually, React creates something similar to:

```js
{
  type: "h1",
  props: {
    children:
      "Three arguments are passed here - Element type, attribute/props and children"
  }
}
```

The exact internal React object contains additional React-specific information, so we should not depend on its internal structure.

The important idea is:

```text
React.createElement()
        ↓
Returns a React Element object
        ↓
JavaScript description of the UI
        ↓
React processes/reconciles the element tree
        ↓
React DOM applies the necessary changes to the browser DOM
```

For example:

```js
const heading = React.createElement(
  "h1",
  {},
  "Three arguments are passed here - Element type, attribute/props and children",
);
```

At this point, `heading` is a **React Element**, not an actual browser `<h1>` DOM node.

When we later write:

```js
root.render(heading);
```

React examines the React Element and determines what needs to be rendered or updated in the browser.

The resulting DOM is effectively:

```html
<h1>
  Three arguments are passed here - Element type, attribute/props and children
</h1>
```

# `React.createElement()` vs JSX

This:

```js
React.createElement("h1", {}, "Hello React!");
```

represents the same UI as:

```jsx
<h1>Hello React!</h1>
```

JSX is therefore a more readable way of describing React elements.

### Key Takeaway

```text
React.createElement()
        ↓
React Element (JavaScript representation)
        ↓
React rendering/reconciliation
        ↓
Actual DOM element in the browser
```

`React.createElement()` creates a **description of the UI**, while React DOM is responsible for turning that description into actual DOM updates.

# Advantages of JSX

- JSX as variables : markup (html-like) syntax can be set in a variable. This creates a react element (object).
- Javascript expressions in JSX : JSX supports all js expressions by wrapping them in {}
- Attributes in JSX : We can pass all the html attributes inside jsx tag (attributes must be CamelCased). Even, custom attributes can be created, but it must not use CamelCase.
- Props in JSX : The values of each attribute can be passed as properties (props) to a react element. This is my favourite superpower of jsx, since it can handle dynamic data to create react elements.

```
const Heading = () => {
        <div>
                <h1>{5+3}</h2>
                <h2>This is a Javascript expression in JSX</h1>
        </div>
}
```

# What are the types of components in React?

React mainly has two types of components:
1. Functional Based Components – JavaScript functions that return JSX. This is in trend, used in most of the companies.
> **Naming Convention**: PascalCase (e.g., Heading, UserProfile, NavigationMenu).
2. Class Based Components – ES6 classes that extend React.Component. It is no more used, it is an old way of writing code.
```

function App() {
return <h1>Hello, This is a functional component.</h1>;
}

```

```

class App extends React.Component {
render() {
return <h1>Hello</h1>;
}
}

```

# What is the shorthand syntax for an arrow function?

If an arrow function contains only one expression that needs to be returned, we can remove the {} and return keyword.

Normal Syntax
```

const Res = ({ a, b }) => {
const r = a + b;
return <p>The result is: {r}</p>;
};

```
Shorthand Syntax
```

const Res = ({ a, b }) => <p>The result is: {a + b}</p>;

```
Both return the same result.

# What is the difference between a normal function component and an arrow function component in React?

Both are functional components in React and behave the same way from React's perspective.
- Function Declaration:
```
function App() {
return <h1>Hello, This is a functional component.</h1>;
}

```
- Arrow Function:
```
const App = () => {
return <h1>Hello, This is a functional component.</h1>;
};

```
> Both are functional components in React. The main difference comes from JavaScript, not React. Function declarations are hoisted and have their own `this`, whereas arrow functions assigned to `const` are not usable before initialization and inherit `this` from their surrounding scope. In modern React functional components, either syntax can be used.

# What does type="module" mean in a <script> tag?

`type="module"` tells the browser to treat the JavaScript file as an ES Module.

```
<script type="module" src="app.js"></script>
```
This enables ES Module features such as:

```
import something from "./file.js";
export default something;
```
Without `type="module"`, the browser treats the file as a normal/classic JavaScript script, so `import` and `export` syntax will not work and may throw errors like:

```
Cannot use import statement outside a module
```

# What is `defer` in a `<script>` tag?

`defer` tells the browser to **download the JavaScript file in parallel while parsing the HTML, but execute it only after the HTML parsing is complete**.

```html
<script defer src="app.js"></script>
```

This prevents the script from blocking HTML parsing.

**Note:** Scripts with `type="module"` are deferred by default.

# What is a component composition?

Basic Nesting (Component inside Component)
The simplest form of composition is placing one component inside the JSX return statement of another.

```
const Button = () => <button>Click Me</button>;

// App composes Header and Button together
const Card = () => {
  return (
    <div className="card">
      <h2>Welcome Back</h2>
      <Button />
    </div>
  );
};
```
# { TitleComponent } vs { <TitleComponent /> } vs { <TitleComponent> </TitleComponent> } in JSX
`{ TitleComponent }` - This value in jsx is considered as jsx expression or variable. If no such variable is present, no output will be shown in the browser. Console throws the following warning

> index.js:1 Warning: Functions are not valid as a React child. This may happen if you return a Component instead of <Component /> from render. Or maybe you meant to call this function rather than return it.

`{ <TitleComponent /> }` - This value in jsx is meant for rendering a component (i.e) function that return jsx. This is self closing tag.

`{ <TitleComponent> </TitleComponent> }` - This is same as `{ <TitleComponent /> }` if there are no child inside TitleComponent. If there are children, then those values come inside `{ <TitleComponent>`  and `</TitleComponent> }`.
