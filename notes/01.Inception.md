# 1. What is a CDN?

**CDN stands for Content Delivery Network.**

### Interview Answer

> A CDN is a geographically distributed network of servers that caches and serves content from locations closer to users, reducing latency and reducing the amount of traffic handled directly by the application's origin server.

A CDN commonly serves static resources such as:

```text
JavaScript
CSS
Images
Fonts
Videos
Static HTML
Libraries
```

Consider an application whose main server is located in the United States.

Without a CDN:

```text
User in India
     |
     |
     | Long network distance
     |
     ↓
Server in USA
```

With a CDN:

```text
                     Origin Server
                          USA
                           |
                  ┌────────┴────────┐
                  │                 │
             CDN Server        CDN Server
               India             Europe
                  ↑
                  |
             User in India
```

Instead of requesting every static resource from the original server, the user may receive cached resources from a nearby CDN edge server.

---

# 2. Why Do We Use a CDN?

Major benefits include:

### 1. Reduced Latency

Resources can be served geographically closer to the user.

```text
Without CDN

India ───────────────────→ USA Server


With CDN

India ───→ Nearby CDN Server
```

---

### 2. Reduced Load on the Origin Server

Instead of every user requesting a resource from the main server:

```text
User 1 ─┐
User 2 ─┼──→ Origin Server
User 3 ─┘
```

a CDN can cache and serve that resource:

```text
User 1 ─┐
User 2 ─┼──→ CDN
User 3 ─┘
          |
          ↓
      Cached File
```

---

### 3. Caching

Frequently requested assets can be cached at edge locations.

Examples:

```text
react.js
styles.css
logo.png
fonts
images
```

---

### 4. Scalability

Traffic can be distributed across CDN infrastructure rather than always reaching one origin server.

---

### Interview Answer

> A CDN improves delivery performance by caching static content on geographically distributed servers. It can reduce latency, improve scalability, and reduce traffic hitting the application's origin server.

# 3. How Do We Add React Using a CDN?

Historically, a simple way to learn React was to load React directly using `<script>` tags.

For example, the classic React 18-style setup looked conceptually like:

```html
<!DOCTYPE html>
<html>
<head>
    <title>React CDN Example</title>
</head>

<body>

    <div id="root"></div>

    <!-- React -->
    <script
        crossorigin
        src="https://unpkg.com/react@18/umd/react.development.js">
    </script>

    <!-- ReactDOM -->
    <script
        crossorigin
        src="https://unpkg.com/react-dom@18/umd/react-dom.development.js">
    </script>

    <script src="./App.js"></script>

</body>
</html>
```

The old React documentation documented these UMD CDN builds for React 18-era applications. ([React][2])

After loading them, the browser gets globals such as:

```javascript
React
ReactDOM
```

and code can use them.

For example:

```javascript
const heading = React.createElement(
    "h1",
    {},
    "Hello React"
);

const root = ReactDOM.createRoot(
    document.getElementById("root")
);

root.render(heading);
```

---

## Why Was This Useful for Learning?

Because we could start with:

```text
index.html
App.js
```

without initially learning:

```text
Node.js
npm
package.json
node_modules
Parcel
Vite
Webpack
Babel configuration
```

The learning progression could therefore be:

```text
HTML + JavaScript
       ↓
Load React
       ↓
Understand React elements
       ↓
Understand React components
       ↓
Learn npm
       ↓
Learn bundlers/build tools
```

### Interview Answer

> CDN loading is useful for small experiments and learning because we can load the library directly in HTML without first configuring a package manager or build system. For maintained applications, we generally install React through npm and use a modular build environment.

React's current documentation recommends using a modular JavaScript environment for real projects and installing `react` and `react-dom` as packages. ([React][3])

# 4. Important React 18 vs React 19 CDN Difference

This is important for modern interviews.

The traditional files:

```text
react.development.js
react-dom.development.js

react.production.min.js
react-dom.production.min.js
```

were **UMD builds**.

Starting with **React 19, React stopped publishing UMD builds**. The React team recommends ESM-based CDN loading when React needs to be loaded directly through HTML without a traditional build setup. ([React][1])

Therefore this:

```html
<script src=".../react.development.js"></script>
<script src=".../react-dom.development.js"></script>
```

should be understood as the **legacy React 18-style CDN approach**.

---

## React 19-Style ESM CDN Concept

Modern JavaScript allows modules to be loaded through:

```html
<script type="module">
```

Conceptually:

```html
<script type="module">
    import React from "https://esm.sh/react@19/?dev";
    import { createRoot } from "https://esm.sh/react-dom@19/client?dev";

    const root = createRoot(document.getElementById("root"));

    root.render(
        React.createElement(
            "h1",
            null,
            "Hello React"
        )
    );
</script>
```

React officially recommends an ESM-based CDN when a script-tag-based React 19 setup is needed. ([React][1])

For production applications, however, a package-based setup is usually preferable.

# 5. What is Cross-Origin?

To understand **cross-origin**, first understand what an **origin** is.

A web origin consists of:

```text
Protocol / Scheme
       +
Host
       +
Port
```

For example:

```text
https://example.com:443
```

contains:

```text
Protocol = https
Host     = example.com
Port     = 443
```

Two URLs have the same origin only when their scheme/protocol, host, and port match. ([MDN Web Docs][4])

---

## Same-Origin Example

Consider:

```text
https://example.com/products
https://example.com/profile
```

They share:

```text
Protocol → https
Host     → example.com
Port     → same default HTTPS port
```

Therefore:

```text
Same Origin ✅
```

---

## Cross-Origin Example: Different Protocol

```text
http://example.com
https://example.com
```

Different protocol:

```text
Cross-Origin ❌
```

---

## Cross-Origin Example: Different Host

```text
https://example.com
https://api.example.com
```

Different host:

```text
Cross-Origin ❌
```

---

## Cross-Origin Example: Different Port

```text
https://example.com:3000
https://example.com:5000
```

Different port:

```text
Cross-Origin ❌
```

---

### Easy Formula

```text
Origin = Scheme + Host + Port
```

If one of those values differs:

```text
Cross-Origin
```

---

### Interview Answer

> Two resources are cross-origin when their scheme, hostname, or port differs. Browsers apply security rules to interactions between different origins.

The browser's same-origin policy uses this origin concept as a fundamental web security boundary. ([MDN Web Docs][4])

---

# 6. What is the Same-Origin Policy?

Browsers implement a security mechanism called the:

```text
Same-Origin Policy
```

The same-origin policy restricts how documents or scripts from one origin can interact with resources belonging to another origin. ([MDN Web Docs][4])

Imagine:

```text
bank.com
```

and:

```text
malicious-site.com
```

Without browser origin restrictions, JavaScript running on an unrelated website could potentially attempt to read sensitive data belonging to another website.

Conceptually:

```text
malicious-site.com
        |
        | browser security restrictions
        X
        |
        ↓
bank.com/private-data
```

The browser therefore creates security boundaries between origins.

### Interview Answer

> The same-origin policy is a browser security mechanism that restricts scripts from one origin from freely reading or interacting with resources from another origin.

# 7. What is CORS?

**CORS stands for:**

```text
Cross-Origin Resource Sharing
```

CORS is an HTTP-header-based mechanism that allows a server to tell the browser which other origins are permitted to access its resources. ([MDN Web Docs][5])

For example:

```text
Frontend
https://myapp.com

        ↓ fetch()

Backend
https://api.example.com
```

These are different origins.

The backend can respond with a header such as:

```http
Access-Control-Allow-Origin: https://myapp.com
```

This indicates that the server allows that origin to access the response through browser cross-origin requests.

---

## Important Interview Point

CORS is primarily enforced by the **browser**.

The server communicates its policy using HTTP headers.

Conceptually:

```text
Browser
   |
   | Request
   ↓
Server
   |
   | CORS response headers
   ↓
Browser
   |
   ├── Allowed → JavaScript receives response
   │
   └── Blocked → JavaScript cannot access response
```

### Interview Answer

> CORS is an HTTP-header-based mechanism that allows servers to specify which external origins browsers may permit to access their resources.

([MDN Web Docs][5])

# 8. What Does `crossorigin` Mean in a Script Tag?

You may see:

```html
<script
    crossorigin
    src="https://example-cdn.com/library.js">
</script>
```

or:

```html
<script
    crossorigin="anonymous"
    src="https://example-cdn.com/library.js">
</script>
```

The `crossorigin` attribute configures how the browser performs the CORS request for resources such as scripts, images, stylesheets, audio, and video. ([MDN Web Docs][6])

---

## `crossorigin="anonymous"`

```html
<script
    crossorigin="anonymous"
    src="https://cdn.example.com/app.js">
</script>
```

This means the cross-origin request uses CORS without including cross-site credentials such as cookies or HTTP authentication credentials.

For HTML, writing:

```html
crossorigin
```

is equivalent to:

```html
crossorigin="anonymous"
```

([MDN Web Docs][6])

---

## `crossorigin="use-credentials"`

Another option is:

```html
crossorigin="use-credentials"
```

This tells the browser that credentials should be included in the CORS request.

The server must also explicitly permit credentialed requests.

---

## Why Was `crossorigin` Common in React CDN Examples?

One benefit relates to proper cross-origin error reporting.

Without appropriate CORS handling, error information from a cross-origin script can be restricted.

The `crossorigin` attribute allows the browser to fetch the script using CORS rules, assuming the CDN also sends the correct CORS response headers. ([MDN Web Docs][6])

---

## Important Interview Distinction

These are related but **not the same thing**:

```text
Cross-Origin
CORS
crossorigin
```

### Cross-Origin

Describes the relationship between two different origins.

```text
https://site-a.com
https://site-b.com
```

---

### CORS

A protocol based on HTTP headers that controls permitted browser cross-origin access.

```http
Access-Control-Allow-Origin: ...
```

---

### `crossorigin`

An HTML attribute telling the browser how a particular resource should be fetched under CORS rules.

```html
<script crossorigin="anonymous">
```

### Interview Answer

> Cross-origin describes resources coming from different origins. CORS is the HTTP mechanism controlling cross-origin access, while the HTML `crossorigin` attribute configures how an element such as `<script>` performs its cross-origin request.

# 9. React vs ReactDOM

React and ReactDOM serve different responsibilities.

At a high level:

```text
React
  ↓
Describe UI and manage component logic

ReactDOM
  ↓
Render that UI into the browser DOM
```

The current React API documentation explicitly separates the platform-independent React APIs from React DOM's web-specific APIs. ([React][7])

---

## React

Installed as:

```bash
npm install react
```

React provides APIs related to:

```text
Components
Hooks
State
Context
Element creation
Component lifecycle model
UI composition
```

Examples include:

```javascript
useState()
useEffect()
useContext()
createContext()
createElement()
```

---

## ReactDOM

Installed as:

```bash
npm install react-dom
```

ReactDOM provides functionality specifically for web applications running in a browser DOM environment. ([React][7])

For example:

```javascript
import { createRoot } from "react-dom/client";
```

Then:

```javascript
const root = createRoot(
    document.getElementById("root")
);

root.render(<App />);
```

`createRoot` creates a React root associated with a browser DOM node and allows React components to be rendered into it. ([React][8])

---

# 10. `react.development.js` vs `react-dom.development.js`

These filenames refer to the older UMD-style React distributions.

They performed different jobs.

---

## `react.development.js`

This contains the **React core library**.

It exposes functionality such as:

```text
React.createElement()
React.useState()
React.useEffect()
React.createContext()
React.Component
```

For example:

```javascript
const element = React.createElement(
    "h1",
    null,
    "Hello React"
);
```

Here:

```text
React.createElement()
```

comes from the React package.

---

## Example with Hooks

```javascript
function App() {
    const [count, setCount] = React.useState(0);

    return React.createElement(
        "button",
        {
            onClick: () => setCount(count + 1)
        },
        `Count: ${count}`
    );
}
```

The state and Hooks APIs belong to React.

---

# `react-dom.development.js`

This contains the **browser DOM renderer**.

It connects React with the browser.

Conceptually:

```text
React Component Tree
        ↓
     ReactDOM
        ↓
Browser DOM
        ↓
Visible Web Page
```

In the React 18 UMD-style API:

```javascript
const root = ReactDOM.createRoot(
    document.getElementById("root")
);

root.render(
    React.createElement(
        "h1",
        null,
        "Hello React"
    )
);
```

In a modern npm/module-based application, the equivalent API is normally imported from:

```javascript
import { createRoot } from "react-dom/client";
```

([React][8])

---

## Easy Interview Answer

> `react` contains the core APIs for building React components and managing UI logic, while `react-dom` contains the web-specific renderer that connects React to the browser DOM.

# 11. Does React Process JSX?

This is a common misconception.

Consider:

```jsx
const heading = <h1>Hello React</h1>;
```

The browser does not treat JSX as standard JavaScript syntax by itself.

And `react.development.js` does **not simply parse this JSX string in the browser**.

Instead, JSX normally goes through a transformation step.

Conceptually:

```text
JSX

<h1>Hello</h1>

      ↓
JSX Transformer / Build Tool
      ↓

JavaScript understood by React runtime
```

Modern React environments use the modern JSX transform, which React 19 requires. ([React][1])

---

## Older Mental Model

Historically, JSX was commonly explained as transforming:

```jsx
<h1>Hello</h1>
```

into something conceptually similar to:

```javascript
React.createElement(
    "h1",
    null,
    "Hello"
);
```

The important point is:

> JSX is syntax that needs to be transformed. JSX transformation is not one of the jobs performed merely by loading `react.development.js`.

---

## Why Can CDN React Examples Sometimes Use JSX?

If a tutorial uses:

```html
<script type="text/babel">
```

then it has normally also loaded something such as **Babel Standalone**.

Conceptually:

```text
JSX
 ↓
Babel
 ↓
JavaScript
 ↓
React
 ↓
ReactDOM
 ↓
DOM
```

Without a JSX transformer, a basic classic CDN setup should use ordinary JavaScript APIs such as:

```javascript
React.createElement()
```

---

### Interview Answer

> React provides the runtime APIs used by React applications, but JSX itself is syntax that must be transformed into JavaScript by build tooling or a JSX compiler. React does not simply parse JSX because `react.development.js` was loaded.

---

# 12. Why Are React and ReactDOM Separate?

React was designed so its core model is not tied exclusively to the browser DOM.

Conceptually:

```text
               React
                 |
        Component + State Logic
                 |
         ┌───────┴────────┐
         ↓                ↓
     ReactDOM       Other Renderers
         |
         ↓
    Browser DOM
```

ReactDOM specifically contains functionality for **web applications running in browser DOM environments**. ([React][7])

This separation keeps browser-specific APIs outside the React core package.

---

## Simple Analogy

Think of building a house.

```text
React
   =
Architect / Blueprint

ReactDOM
   =
Construction Crew
```

React describes:

```text
What should the UI look like?
What state does it have?
How are components composed?
```

ReactDOM handles:

```text
How does that UI appear inside the browser DOM?
```

Another way to remember it:

```text
React    → WHAT the UI should be

ReactDOM → WHERE/HOW it gets rendered in the browser
```

# 15. Why npm + Bundler is Preferred

Consider a larger application:

```text
src/
├── App.js
├── Header.js
├── Body.js
├── Footer.js
├── Cart.js
├── Product.js
└── utils.js
```

Managing this through manual CDN globals becomes increasingly inconvenient.

A modular setup allows:

```javascript
import React from "react";
```

and:

```javascript
import { createRoot } from "react-dom/client";
```

React's documentation recommends installing:

```bash
npm install react react-dom
```

when integrating React into a modular project. ([React][3])

---

## Benefits

### 1. Proper Dependency Management

Dependencies are recorded in:

```text
package.json
```

and exact resolved dependency information is captured by the lockfile.

---

### 2. ES Modules

We can naturally write:

```javascript
import Header from "./Header";
import Footer from "./Footer";
```

---

### 3. Component Organization

We can split code into:

```text
Header.js
Footer.js
Product.js
Cart.js
```

instead of keeping everything in one file.

---

### 4. Development Server

Tools such as Parcel and Vite provide a local development environment.

---

### 5. Hot Reloading / Fast Refresh

Changes can appear quickly during development.

---

### 6. Production Optimization

Build tooling can perform operations such as:

```text
Bundling
Minification
Code splitting
Tree shaking
Asset processing
Content hashing
```

---

## Interview Answer

> CDN loading is convenient for small demonstrations, but package-based React setups integrate better with modules, dependency management, build tooling, testing, code organization, and production optimization.

# 16. Does the Order of Script Files Matter?

Yes — particularly for **classic scripts that depend on globals created by previous scripts**.

Consider:

```html
<script src="react.development.js"></script>
<script src="react-dom.development.js"></script>
<script src="App.js"></script>
```

The logical dependency chain is:

```text
React
  ↓
ReactDOM
  ↓
Our Application
```

---

## Why Must React Come Before ReactDOM?

ReactDOM depends on React functionality.

So React must already be available before the classic ReactDOM UMD script executes.

Correct:

```html
<script src="react.development.js"></script>
<script src="react-dom.development.js"></script>
```

Incorrect:

```html
<script src="react-dom.development.js"></script>
<script src="react.development.js"></script>
```

The second order may cause dependency-related errors because ReactDOM expects React to exist.

---

## Why Must `App.js` Come After Both?

Suppose `App.js` contains:

```javascript
const root = ReactDOM.createRoot(
    document.getElementById("root")
);
```

If:

```text
ReactDOM
```

has not been loaded yet, JavaScript may throw:

```text
ReferenceError: ReactDOM is not defined
```

Similarly, if the application uses:

```javascript
React.createElement(...)
```

before React loads:

```text
ReferenceError: React is not defined
```

---

## Correct Dependency Order

```html
<script src="react.development.js"></script>
<script src="react-dom.development.js"></script>
<script src="App.js"></script>
```

Think:

```text
Dependency
    ↓
Dependent
    ↓
Application
```

---

## But There Is an Important `async` Exception

Consider:

```html
<script async src="react.js"></script>
<script async src="react-dom.js"></script>
```

With `async`, scripts execute as soon as they finish downloading.

Therefore:

```text
Download completion order
        ↓
Execution order
```

may differ from:

```text
HTML order
```

So `async` should not be used when classic scripts depend on a strict execution order unless the dependencies are otherwise coordinated.

---

## ES Modules Are Different

With modern modules:

```javascript
import React from "react";
import { createRoot } from "react-dom/client";
```

the module system explicitly defines dependencies.

Conceptually:

```text
App.js
 │
 ├── imports React
 │
 └── imports ReactDOM
```

This is much more maintainable than manually managing global script order.

---

### Interview Answer

> Script order matters when one classic script depends on globals created by another. React must load before the legacy ReactDOM UMD build, and both must load before application code using them. Module-based applications handle dependencies explicitly through `import` statements.

---

   React CDN Script                 ReactDOM CDN Script

          ↓                                 ↓

          └──────────────┬──────────────────┘

                  React Component

                         ↓

# 18. Quick Interview Revision

## What is CDN?

> A CDN is a geographically distributed network of servers used to serve cached content from locations closer to users, reducing latency and origin-server traffic.

---

## What is an Origin?

```text
Origin = Scheme + Host + Port
```

---

## What is Cross-Origin?

> Two resources are cross-origin when their scheme, host, or port differs.

([MDN Web Docs][4])

---

## What is Same-Origin Policy?

> It is a browser security mechanism restricting how content from one origin can interact with resources belonging to another origin.

([MDN Web Docs][4])

---

## What is CORS?

> CORS is an HTTP-header-based mechanism through which servers specify which other origins a browser may allow to access their resources.

([MDN Web Docs][5])

---

## What is `crossorigin`?

> `crossorigin` is an HTML attribute that configures how elements such as `<script>` perform cross-origin requests using CORS.

([MDN Web Docs][6])

---

## What Does React Do?

```text
Components
Hooks
State
Context
Element creation
UI logic
```

---

## What Does ReactDOM Do?

```text
React UI
   ↓
Browser DOM
```

ReactDOM contains React's web-specific rendering APIs. ([React][7])

---

## Does React Convert JSX?

> Not by simply loading the React library. JSX requires a transformation step performed by appropriate tooling.

React 19 requires the modern JSX transform. ([React][1])

---

## React vs ReactDOM?

```text
React
   ↓
Core UI/component model

ReactDOM
   ↓
Browser-specific renderer
```

---

## Development vs Production Build?

```text
Development
   ↓
Warnings + checks + debugging help

Production
   ↓
Optimized deployment code
```

---

## Is `react.development.js` the Modern React 19 CDN Setup?

> No. That filename comes from the older UMD distribution. React 19 removed UMD builds and recommends ESM-based CDN loading when a direct script-based approach is required.

([React][1])

---

## Should We Use CDN for a Production React App?

Usually:

```text
Learning
   ↓
CDN can be useful

Maintained application
   ↓
npm + modular build environment
```

React's current documentation recommends a modular setup for adding React to an existing application. ([React][3])

---

## Should We Use Create React App for a New Project?

> No. Create React App is deprecated for new applications.

The React team recommends current frameworks where appropriate or build tools such as Vite, Parcel, or RSBuild for custom setups. ([React][9])

---

## Does Script Order Matter?

For classic global scripts:

```text
React
  ↓
ReactDOM
  ↓
App.js
```

Yes.

Dependencies must be available before code that uses them.

# Final One-Line Mental Model

> **A CDN delivers files, React defines the component/UI model, ReactDOM connects React to the browser DOM, CORS controls permitted cross-origin browser access, JSX requires transformation, and modern production applications generally install React through npm rather than relying on legacy UMD CDN scripts.**
